# ADR-0001 앱 스택: Next.js + Supabase + Claude

- 날짜: 2026-10-16
- 상태: 확정

## 결정
| 항목 | 설계서 (이전) | 바꾼 것 |
|---|---|---|
| 화면 | Apps Script 웹앱 | Next.js 16 (App Router) — `apps/web` |
| 원본 데이터 | Google Sheets | Supabase(Postgres, 서울 리전) |
| AI 모델 | Gemini | Claude |
| 레이아웃 | — | D2 벤토 그리드 (Figma 시안) |

## 이유
- 역할 4개·권한·잠금·감사 로그를 시트 수식과 Apps Script로 관리하기 어렵다.
- 학생 등록, 상담 기록처럼 동시에 여러 사람이 쓰는 데이터는 트랜잭션이 필요하다.
- 시안(벤토 그리드, 영랑이, 모바일 412)을 Apps Script HTML로 옮기기 어렵다.

## PRD 조건과의 관계 (§12)
- **C8 (시트가 유일한 원본)**: Supabase가 원본으로 바뀐다. 시트는 내보내기(백업·담임 전달)로만 쓴다.
- **C2 (화면 요청 경로에서 LLM 금지)**: 2026-10-16 사용자 결정("거의 모든 부분에 AI 기능")으로 **버튼을 누른 AI 작업**을 예외로 넓힌다. 처음 예외는 영랑이 하나였다. 조건은 다음과 같다.
  - 사람이 버튼을 눌렀을 때만 서버에서 부르고(`lib/server/ai/claude.ts` 하나로), API 키는 브라우저에 두지 않는다 (C1).
  - 이름·학번은 보내지 않고 가명ID(S001…)만 보낸다. 교사 메모·서류 글은 보내기 전에 이름·학번을 가린다.
  - 결과는 "초안·제안"으로만 보여 주고, 사람이 "확인 후 ○○"을 눌러야 반영한다. 자동 저장·자동 전송은 없다.
  - 키가 없으면 규칙 기반 결과("자동")나 직접 입력으로 이어간다.
- **이미지·PDF를 그대로 읽는 예외** (이름이 적힌 원본이 AI로 간다 — 학교 승인 전에는 `ANTHROPIC_API_KEY`를 비워 두면 모두 꺼진다):
  1. 봉사활동 확인서 읽기 (교사 업로드)
  2. 제출 서류의 학생 연결·합본 PDF 쪽 나누기 (T6·T7) — 이름은 연결에만 쓰고 초안을 만들기 전에 가린다
  3. 성적표 사진 읽기 (H3) — 번호 열만 읽게 하고 출력에 이름 칸이 없다. 이름은 서버가 명렬표로 붙인다
  - 교사가 올린 계획서·기안문, 모집요강, 편제표 이미지는 학생 개인정보가 아니라서 예외가 아니다.
- 나머지 C1, C3~C7, C9, C10은 그대로 지킨다.
