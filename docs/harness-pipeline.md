# 하네스 파이프라인 (harness-pipeline)

> 확정: R3, 2026-10-16
> 기준 문서: `docs/story-work.md`, `docs/harness-purpose.md`

## 흐름

```
[S1 수집·점검] → [S2 초안 작성] → [S3 자동 검사] → [S4 교사 확정] → [S5 전달 묶음]
                       ▲               │ 실패           │ 반려
                       └───────────────┴────────────────┘
```

## 단계별 입출력

| 단계 | 입력 | 출력 | 원래 손작업 |
|---|---|---|---|
| S1 수집·점검 | 프로그램 정보, 명단, 응답 CSV(가명) | 응답 점검표, 미응답 명단 | 3 ⏸ |
| S2 초안 작성 | 점검된 응답, 희망진로, 규칙 SSOT | 학생별 초안 N개 | 4 ⏸ |
| S3 자동 검사 | 학생별 초안 | 검사 결과 (통과/실패, 사유) | 5 ⏸ |
| S4 교사 확정 | 검사 통과 초안 (+ 수동 작성 필요 건) | 확정 표시 N건 | 새 단계 (N1) |
| S5 전달 묶음 | 확정본, 미응답 명단 | 담임 전달 파일 1개 | 6 ➡ |

## 처리 단위

- 학생 1명 = 처리 단위 1개.
- S2·S3는 학생별로 실행한다.
- S4는 전원 분량을 **한 번에 모아** 교사에게 보여준다 (사람 승인 지점 1곳).

## 미응답 처리

- 응답한 학생만 S2로 진행한다.
- 미응답자는 미응답 명단에 남기고, 교사가 사유를 적는다.
- 미응답자 사유 칸이 비어 있으면 S5를 막는다.

## 되돌아가는 지점

| 출발 | 도착 | 조건 | 횟수 |
|---|---|---|---|
| S3 실패 | S2 | 검사 실패 사유를 입력으로 넣는다 | 학생 1명당 최대 3회. 넘기면 "수동 작성 필요" 표시 후 S4로 |
| S4 반려 | S2 | 교사 반려 사유를 입력으로 넣는다 | 제한 없음 |
