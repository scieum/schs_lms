# 속초고 학업·생기부 통합 관리 시스템 PRD

> **문서 상태**: 초안 v0.1 (2026-10-16)
> **출처**: `속초고_통합관리시스템_설계서.md` v1.0 (2026-07-15). 이 PRD는 설계서에 있는 내용만 제품 관점으로 다시 묶은 문서입니다. 설계서에 없는 내용은 `⚠ 확인 필요`로 표시했습니다.
> **설계서와의 관계**: PRD는 "무엇을, 누구를 위해, 어디까지"를 정하고, 설계서는 "어떻게 만드는가"(아키텍처, 시트 스키마, 폴더 구조)를 정합니다. 둘이 충돌하면 확인 전까지 작업을 멈춥니다.

## 1. 배경

속초고등학교의 학생 기록은 지금 여러 곳에 흩어져 있습니다.

- **설문지**: 프로그램이 끝날 때마다 따로 만들어 걷는 학생 활동 기록
- **한글 파일**: 생기부 문안, 성적 자료
- **개별 교사 메모**: 상담 내용
- **기존 야자 시스템**: 야간자율학습 신청·출석 (별도 시스템)

그래서 기록을 쌓아 두고 다시 쓰기 어렵습니다. 학생 활동이 생기부 문장이 되기까지 교사가 매번 손으로 옮겨 적어야 하고, 같은 학생의 기록을 다른 교사가 이어 보기도 어렵습니다.

이 시스템이 해결해야 하는 문제는 다음과 같습니다.

1. 학생 활동이 끝나면 **같은 형식의 설문으로** 기록이 모여야 합니다.
2. 모인 설문으로 **생기부 초안이 자동으로 만들어지고**, 교사는 검토·확정만 해야 합니다.
3. 기존 생기부 PDF, 성적, 상담, 제출물이 **학생 한 명 단위로 쌓여야** 합니다.
4. 학생·교사가 **역할에 맞는 권한 안에서만** 기록을 볼 수 있어야 합니다.
5. 흩어진 운영 업무(야자, 과목 신청)를 **한 시스템 안으로** 모아야 합니다.

## 2. 제품 비전

> 학생 활동이 발생하면 → 정형화된 설문으로 수집되고 → 생기부 초안이 자동 생성되며 → 교사가 검토·확정하고 → 학생·교사가 역할별 권한 안에서 누적 데이터를 조회하는 **단일 파이프라인**.

장기 목표는 리더스쿨·슈퍼스쿨 수준의 종합 학사 시스템을 학교가 직접 갖추는 것입니다. 이 PRD는 그중 **1차 MVP 범위**를 정합니다.

## 3. 핵심 유저스토리

### 3-1. 학생으로서

**학생으로서**, 대시보드에서 아직 응답하지 않은 프로그램 설문과 남은 기간(D-day)을 확인하고 바로 제출하고 싶다. 내 성적 추이, 수능 최저 충족 여부, 전년도에 확정된 내 생기부, 나에게 추천된 도서·과목·후속 활동을 한곳에서 보고 싶다. 야자 신청과 과목 신청도 같은 곳에서 하고 싶다.

### 3-2. 프로그램 담당 교사로서

**프로그램 담당 교사로서**, 프로그램을 등록하면 공통 설문이 자동으로 만들어져 대상 학생에게 나가고, 누가 응답했는지 바로 보고 싶다. 응답이 들어오면 생기부 초안이 자동으로 만들어져 있어서, 나는 검토·수정·확정만 하고 싶다.

### 3-3. 교과교사로서

**교과교사로서**, 내 교과 학생의 세특 초안을 검토·확정하고, 담당 학생의 성적과 제출물을 보고 싶다. 내가 쓴 상담 기록을 남기고 다시 보고 싶다. 다른 교과교사가 쓴 상담 기록은 볼 수 없어야 한다.

### 3-4. 담임교사로서

**담임교사로서**, 반 학생의 성적·설문 응답·상담 기록을 한 화면에서 보고 싶다. 성적 파일을 올리고, 반 학생의 수능 최저 충족 여부를 한 번에 보고 싶다. 다른 교사가 쓴 상담 기록을 포함해 반 학생의 상담 기록 전체를 보고, 반 학생의 야자를 관리하고 싶다.

### 3-5. 어드민(관리 교사)으로서

**어드민으로서**, 학생·교사 명부를 올려 계정을 만들고, 비밀번호 초기화와 인증코드를 관리하고 싶다. 전교 프로그램 일정, 초안 자동 생성이 실패한 건(ERROR 큐), 감사 로그를 확인하고 싶다.

> ⚠ 확인 필요: 학부모는 설계서의 역할(학생·교사·어드민)에 없습니다. MVP 범위 밖으로 보아도 되는지 확인이 필요합니다.

## 4. 사용자들의 상황

설계서에서 확인되는 사실만 적었습니다.

- 교사 한 명이 **담임·교과·프로그램 담당·어드민 역할을 동시에** 가질 수 있습니다.
- 생기부 문안은 **NEIS 글자수 규정**을 지켜야 하며, AI가 쓴 초안은 위험도가 높은 산출물이라 반드시 교사가 확정해야 합니다.
- 상담 기록과 성적은 **민감한 개인정보**입니다. 누가 무엇을 볼 수 있는지가 역할에 따라 비대칭입니다.
- 학생은 **당해연도** 교사가 쓴 생기부(초안·확정본)를 볼 수 없고, **전년도 확정본**만 볼 수 있습니다.
- 교사는 비밀번호를 잃어버려도 **스스로 복구할 수단이 없고**, 어드민 초기화만 가능합니다.
- 학생과 교사 모두 **PC와 모바일**에서 사용합니다.

> ⚠ 확인 필요: 학생 수·교사 수 규모. 설계서에는 MVP 시나리오 기준 "학생 30명"만 나와 있습니다.

## 5. 핵심 정보 구조 (역할별 홈)

```txt
[학생 홈]
D-day 프로그램 카드(미응답 설문 배지) / 내 성적 추이 미니차트 /
전년도 생기부 열람 / 활동 연결 그래프 / 추천(도서·과목·후속 활동) / 야자 신청

[교과·프로그램 교사 홈]
내 프로그램 응답률 / 검토 대기 초안 큐(배지) / 담당 학생 목록 / 상담 입력

[담임 홈]
반 학생 그리드(성적·응답·상담 통합 진입점) / 성적 업로드 /
최저 판정 일괄 뷰 / 야자 관리

[어드민 홈]
전교 프로그램 캘린더 / 계정 관리(초기화·인증코드) /
시트 상태 모니터(초안 생성 ERROR 큐) / 감사 로그
```

공통: PC는 사이드바, 모바일은 하단 탭 바로 레이아웃을 나눕니다(별도 앱 아님). 다크모드를 지원합니다(시스템 설정 감지 + 수동 토글).

## 6. 기능 요구사항

### F1. 계정/권한

필수 기능:

1. 어드민이 학생·교사 명부를 올리면 계정 일괄 생성 (초기 비밀번호 = 공통 인증코드)
2. 로그인: 교사는 이름 + 비밀번호, 학생은 학번 + 비밀번호
3. 첫 로그인 시 **비밀번호 변경 강제** (변경 전에는 다른 화면 진입 불가)
4. 비밀번호 분실: 어드민이 초기화 (학생·교사 모두)
5. 로그인 5회 실패 시 10분 잠금

통과 기준: 명부에 학번·이름 중복 없음, 새 비밀번호는 인증코드와 다르고 8자 이상.

### F2. 프로그램·설문

필수 기능:

1. 교사가 프로그램 등록 (분류: 창체 / 진로 / 교과, 대상 학생 지정)
2. 공통 설문 자동 생성: **고정 4문항**(활동 내용 / 배운 점 / 느낀 점 / 후속 계획) + 프로그램별 추가 0~2문항
3. 발행 시 대상 학생 전원에게 노출
4. 학생 대시보드에 D-day 카드와 미응답 배지
5. 응답 제출 (필수 문항 답변 필요, 문항당 최소 글자수 예: 30자)
6. 응답률 대시보드 (응답/미응답 명단, 리마인드 대상 추출)

### F3. 생기부 초안 자동 생성 ★ 핵심

필수 기능:

1. 설문 응답이 들어오면 자동으로 초안 생성 시작 (사람 개입 없음)
2. 프로그램 분류(창체 / 진로 / 교과세특)에 따라 다른 방식으로 초안 작성
3. 초안 입력: 설문 답변 + 학생 희망진로 + 프로그램 개요
4. 초안 자동 검사: NEIS 글자수 이내, 학생 이름·학번 미포함, 설문의 핵심 활동 반영
   - **분량은 교사가 생성할 때 정한다** (2026-10-16): 단위(바이트/글자)와 최대 분량을 고른다. 기본값은 분류별 NEIS 한도, 한도를 넘는 값은 고를 수 없다(C7). 하한은 최대의 60%.
5. 실패 시 최대 3회 자동 재시도 → 그래도 실패하면 교사 화면에 "수동 작성 필요" 표시
6. 교사 검토 화면: 초안 확인 → 수정 → **확정** (반려 시 초안으로 되돌리고 사유 기록)

초안 처리 상태:

- `PENDING` 대기
- `RUNNING` 생성 중
- `DONE` 초안 완료
- `ERROR` 실패 (사유 기록)

생기부 기록 상태:

- `draft` 초안
- `finalized` 확정 (교사만 전환 가능)

### F4. 생기부 PDF 파싱

필수 기능:

1. 교사가 기존 생기부 PDF 업로드
2. 항목별 분해: 교과발달 / 세특 / 창체 / 행특 / 출결
3. 교사 확인 화면에서 원문과 대조해 **승인**
4. 일부 페이지만 실패하면 성공한 부분은 살리고, 실패 페이지는 수동 입력 안내

### F5. 성적 관리 + 수능 최저 판정

필수 기능:

1. 담임이 모의고사·내신 성적 파일(xlsx/csv) 업로드
   - **모의고사 과목은 공통과목 그대로 쓴다** (2026-10-16): 국어·수학·영어·한국사·통합사회·통합과학. 수학 선택과목(미적분·확률과 통계 등)이나 사탐·과탐 과목으로 나누거나 바꾸지 않는다.
2. 학번이 하나라도 매칭되지 않으면 **전체 취소** (부분 반영 금지), 실패 행 목록 표시
3. 과목별 등급 추이 차트
4. 대학·전형별 최저 기준 대비 **충족 / 미충족 / 근접** 판정
5. 판정 규칙을 읽을 수 없는 대학은 "판정 불가"로 표시

### F6. 상담기록

필수 기능:

1. 교사가 학생 페이지에서 상담 메모 입력
2. 수정은 덮어쓰기가 아니라 **새 버전 추가** (삭제 불가)
3. 열람은 §7 권한 구조를 따름 (교과교사: 본인 작성분만 / 담임: 반 학생 전체)

### F7. 활동 연결 추천

필수 기능:

1. 학생의 활동 기록끼리 비슷한 것을 위키처럼 연결
2. 연결된 활동을 바탕으로 후속 활동 제안 (제안 이유 포함)
3. 학생·교사 화면에서 연결 그래프 보기

통과 기준: 기록이 3건 이상인 학생은 연결 1건 이상. 실패해도 다른 기능을 막지 않습니다(선택 기능).

### F8. 도서 추천

필수 기능:

1. 희망진로 + 최근 활동 기반으로 도서 3권과 추천 사유
2. 추천 사유에 근거가 된 활동 기록 연결

> ⚠ 미결(OI-9): 존재하지 않는 책을 추천하지 않도록 ISBN 대조 소스를 쓸지 결정 필요.

### F9. 제출물 OCR

필수 기능:

1. 학생이 PDF/이미지 제출물 업로드
2. 글자 인식 결과 저장
3. 교사가 초안을 다시 만들 때 보조 자료로 선택 가능
4. 실패해도 원본은 보존 (다른 기능 비차단)

### F10. 야자 시스템

필수 기능:

1. 기존 야자 데이터 이관
2. 학생: 신청 / 조회
3. 담임: 반 학생 관리, 출석·통계

야자 상태: `신청` / `출석` / `결석` / `취소`

> ⚠ 미결(OI-6): 기존 코드를 합칠지, 데이터만 옮길지.

### F11. 과목 신청·추천

필수 기능:

1. 어드민이 과목 개설 → 신청 기간 오픈
2. 학생이 우선순위를 매겨 신청
3. 정원 초과 시 처리 (⚠ 미결 OI-7: 선착순 / 추첨 / 담임 조정)
4. 확정 명단 xlsx 내보내기
5. 진로 기반 차년도 과목 3개 추천 — **개설된 과목 안에서만** 추천

### F12. 편제표 · 교과 세특 (2026-10-16 추가)

과목 체계: 2022 개정 교육과정 **교과(군) → 과목**(공통 / 일반·진로·융합 선택). 목록은 `apps/web/src/lib/domain/curriculum.ts`.

1. **편제표** (관리자): 학년도·학년·학기마다 개설 과목과 학점을 넣는다. 교과 → 과목을 고르고, 2022 개정에 없는 과목(2015 개정을 배우는 3학년, 교육감 승인·계열 과목)은 "직접 입력"으로 넣는다. 이름은 띄어쓰기·Ⅰ/1 차이를 자동으로 맞춘다. 과목은 지우지 않고 내린다.
2. **내 교과·과목** (교사, 관리자는 다른 교사 것도): 교과 고르기 → 그 교과의 개설 과목 고르기 → 과목마다 맡은 반 고르기.
3. **교과 세특** (교사): 내 과목 → 수강 학생(과목 학년 + 맡은 반) → 학생별 작성. 분량(바이트/글자)은 교사가 정하고 NEIS 한도를 넘을 수 없다(C7). 임시 저장·확정 모두 새 버전으로 추가한다(C4). 확정은 분량 초과 시 막는다.
4. 선택과목 수강생 명단(반이 섞인 수업)은 다음 단계 — 지금은 "학년 + 맡은 반"으로 정한다.

### F13. 나이스 반영 (2026-10-16 추가)

나이스에는 쓰기용 공식 API가 없어서, 상용 서비스처럼 **크롬 확장 프로그램**이 교사가 열어 둔 나이스 입력 화면에 값을 채운다 (`apps/neis-extension`).

1. 교과 세특 화면 › "나이스로 내보내기": 확정한 세특만 JSON(`schs-neis/1`)으로 받는다. 감사 로그에 남긴다.
2. 확장 프로그램: 파일 불러오기 → 반 고르기 → 덮어쓰기/이어쓰기 → 학생 줄을 **번호+이름**으로 찾아 채움 → 바이트 초과·이름 불일치·화면에 없음을 알려 준다.
3. **저장 버튼은 교사가 직접 누른다** (자동 저장 금지). 불러온 자료는 30분 뒤 자동 삭제, 서버로 보내지 않는다.
4. 실제 나이스 화면의 선택자는 교사 화면(F12)에서 확인해 맞춘다. 학교·교육청 정보보안 지침상 사용 가능한지 먼저 확인한다.
5. 다음 대상: 행동특성 및 종합의견, 창체 특기사항, 누가기록 (같은 파일 형식 `kind`만 바꿔서)

## 9. MVP 범위

### MVP 1차 — F1~F11 전 기능

설계서 기준 1차 MVP는 F1~F11을 모두 포함합니다. 단, 만드는 순서는 §10 로드맵을 따르고, **F3(초안 파이프라인)이 검증되기 전에는 그 뒤 기능을 만들지 않습니다.**

## 12. 조건 (불변 제약)

아래 조건은 어떤 단계에서도 어길 수 없습니다. 어기면 빌드를 멈춥니다.

| # | 제약 |
|---|---|
| C1 | 브라우저(클라이언트)에 API 키를 절대 노출하지 않는다. |
| C2 | 웹앱 화면 요청·응답 경로에서 AI(LLM)를 직접 부르지 않는다. AI는 기록을 "쓰는 시점"의 배치 작업에만 쓴다. **예외: 영랑이(가명ID만 전송, 초안만 표시) — ADR-0001** |
| C3 | 학번·이름을 URL에 절대 넣지 않는다. 조회 URL은 의미 없는 UUID만 쓴다. |
| C4 | 생기부 확정본·상담기록은 지우거나 덮어쓰지 않는다. 수정은 새 버전 추가로만 한다(어드민 소프트 삭제만 허용). |
| C5 | 학생은 당해연도에 교사가 쓴 생기부(초안·확정본)를 볼 수 없다. 전년도 확정본만 본다. |
| C6 | 상담기록: 교과교사는 본인 작성분만, 담임은 반 학생 전체, 학생과 다른 교과교사는 볼 수 없다. |
| C7 | 생기부 초안은 NEIS 글자수 제한을 넘을 수 없다 (세특 500자, 그 외 항목 기준은 OI-5에서 확정). 교사가 정하는 분량도 이 한도 안에서만 고를 수 있다. |
| C8 | ~~Google Sheets가 유일한 원본이다.~~ **Supabase(Postgres)가 원본이다. 시트는 내보내기용 — ADR-0001** |

| C10 | AI가 만든 초안은 교사가 확정해야만 "확정" 상태가 된다. 자동 확정 금지. |

## 14. 이렇게 평가해요

### 파이프라인 완성도

설문 → 초안 → 검토 → 확정 → 열람이 사람 손 없이(교사 검토 제외) 이어지는지 봅니다. 설문과 생기부가 따로 노는 수준이라면 핵심 문제를 해결하지 못한 것입니다.

### 권한 정확성

같은 학생 기록이라도 학생·교과교사·담임·프로그램 담당·어드민에게 다르게 보이는지 봅니다. 특히 상담기록 비대칭(C6)과 학생의 당해연도 생기부 차단(C5)이 테스트로 증명되어야 합니다.

### 기록 무결성

확정본과 상담기록이 지워지거나 덮어써지지 않고, 모든 수정이 버전으로 남는지 봅니다.

### AI 산출물 안전성

AI 초안이 글자수·개인정보 검사를 통과하지 못하면 저장되지 않는지, 교사 확정 없이 확정되지 않는지 봅니다.

### 사용 편의

학생은 D-day 카드에서 바로 응답하고, 교사는 검토 대기 초안을 한 큐에서 처리할 수 있는지 봅니다. PC와 모바일, 라이트와 다크 모드 모두에서 확인합니다.
